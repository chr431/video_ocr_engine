# 2026-09-14 GPU 侧立项轮：OCR-bound 定量 + 三条路线的实测裁决

> 命题（用户授权）：hybrid 稳定后若 GPU-bound，GPU 侧优化可进行。
> 本轮交付：h264 OCR-bound 的精确定量、fp16/CUDA Graph/批三条路线的
> 实测裁决（两条被堵、一条已知非杠杆）、发布门禁 19/19 复绿 +
> 消融步口径修正。**产品行为零变更**（全部改动为探针/门禁/旋钮注册）。

## 0. 定量：h264 引擎级已 OCR-bound，且瓶颈是 launch 裸奔

h264-hybrid 全片（wall 3.4s）分相：decode 2.5s ∥ ocr 3.0s；ocr.infer
n=153 sum=2.1s **p50 12.2ms/批**。生产批形状分布（打桩
`_prepare_shape` 实录）：**B=18/W=224 ×150 + 尾批 ×3**——全部窄批。

裸 TRT 微基准（同形状 B=18/W=224）：

| 方式 | 单发延迟 |
|---|---:|
| 紧循环（30 次摊销，全流水） | **5.6ms** |
| 单发（enqueue+sync，无流水） | 7.1~10.1ms |
| CUDA Graph replay（独立验证） | **5.69ms** |

⇒ 生产 p50 12.2ms 与裸吞吐 5.6ms 的差额 = **launch 裸奔**：infer 线程
逐批"提交-等完"，CPU 提交（TRT 内部数百 kernel 的逐个 launch）慢于
GPU 执行，GPU 在批内挨饿。并发争用已排除（并发解码+分段时裸 TRT
5.2~8.7ms，无系统性膨胀）。

## 1. 路线一：CUDA Graph——机制独立成立，管道内被 TRT 重排层堵死

实现（已回退，原因见下）：`execute_device_argmax` 单子批按
(shape,in,out,epoch) 捕获 [enqueue + argmax 归约 + D2H 到固定 pinned]，
replay 折叠 launch。缓冲 realloc → epoch++ 全图失效（防悬垂）。

**独立验证全部通过**：捕获 OK、instantiate OK、replay 输出与常规路径
**逐位一致**、单发 5.69ms（≈吞吐值，launch 折叠生效）。

**管道内三连否**：
1. `set_input_shape` 在捕获区内 → TRT genericReformat 构建期触不兼容
   API（cudaError 401）。修法=形状/地址先设后捕——独立场景由此全绿。
2. 管道内仍 401→901 级联：并发 malloc/free、跨线程 ctx、暖机次数
   三个嫌疑逐一被独立实验排除后，差异点收窄到管道运行时环境本身
   （未最终定位）。
3. **决定性否决**：失败的捕获尝试会**毒化 CUDA 上下文**——decord
   生产者线程随后死于 `cuda_device_api.cc:231 initialization error`
   （rc=1 整管线崩）。这不是性能问题而是安全问题，任何"捕获失败回落
   常规"的设计都不成立。**已整体回退，连消融旋钮一并删除。**

（插曲留档：调试中途一个裸枚举名笔误 `cudaStreamCaptureModeThreadLocal`
——它在 `cudaStreamCaptureMode` 命名空间下——让 152 次尝试全走
AttributeError 回落且产生了无法解释的 2.83s 快读数；该读数与 GPU
时钟态相关，不可作为任何结论依据。独立复现请用命名空间枚举。）

## 2. 路线二：fp16——TRT 11.2 已删光精度 builder flag

`BuilderFlag` 成员实测仅 DEBUG/TF32/SPARSE 等，**FP16/HALF/INT8/BF16
全无**。半精度只剩 `NetworkDefinitionCreationFlag.STRONGLY_TYPED` +
fp16 ONNX 一条路——但那样 IO 也是 half，预处理/归约整条链路要联动
改造，且必须过逐帧真值准确率门禁（C-15 纪律）。工程量与风险均超
本轮授权范围，**留档为明确的立项选项**（预期收益：ocr.infer 的纯
GEMM/卷积部分 ~1.5-2×，对 h264 wall 约 −15~25%）。

## 3. 路线三：批尺寸——已知非杠杆（复确认）

OCR_BATCH 16→64 同进程交错（前轮）：h264 符号混乱、hevc 混合——漂移
内。TRT_PROFILE_BATCH 已是 18（S6 轮实测 6→18 −16% 落袋）。
W=672 时裸 TRT 19.5ms（超线性）——但生产实测全在 W=224，宽批问题
在当前素材不存在。

## 4. 发布门禁复绿 + 消融步口径修正

完整门禁（已装 wheel，新架构）：gold 28/28 / fast 6 例 / slow 4 例
（含 bf16 酷刑流）/ stress bad=0 / corrupt 6 例（截断 60%/90% + 中段
坏字节 × 双路径）全部通过。消融步判定修正：**新架构里泵内流序 kick
是纯优化而非承重**——`DECORD_HYBRID_KICK_OFF=1` 全禁后段数 8340 不变
（离场侧 DPB 尾由其下一被供 GOP 的 IDR 天然冲刷）。消融步从"期望
挂死"改为**优雅降级守护**（禁 kick 必须仍 8340 完成，防回退成
"kick 是唯一活路"的脆弱形态）。
