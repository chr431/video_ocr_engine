# 2026-09-15 TRT 11.3 + CUDA 13.4.1 评估：无性能收益，环境已回滚

> 命题（用户）：F 盘有 TRT 11.3.0.99（cuda-13.4）与 CUDA 13.4.1 安装包，
> 临时安装测试是否能提高性能。测试基线 = TRT 11.2.1.2 + toolkit 13.3。

## 结论

| 维度 | TRT 11.2（基线） | TRT 11.3 |
|---|---|---|
| 推理 p50（B18/W224 原生 plan，n=50） | 8.95ms | 9.04ms（**持平**） |
| 首次引擎构建 | 68s（历史） | 63.1s |
| 11.2 plan 兼容加载 | — | 可加载（MVC）但慢 ~12%（10.04ms）→ 需原生重建 |
| e2e（h264-hybrid 全片冷池） | ~3.0-3.5s 带 | 3.89s（同带） |

**判定：无收益不升级。** CUDA 13.4.1 亦无需安装——TRT 11.3 在 13.3
runtime（cudart64_13 major 兼容）下加载运行正常。

## 过程要点

- 临时安装方式 = zip 解压 + PATH/add_dll_directory 前置 11.3 lib +
  force-reinstall 11.3 cp313 bindings wheel（--no-deps）；进程级生效，
  系统零持久化。
- **缓存兼容性（重要发现）**：TRT 10+ 的 minor version compatibility
  默认开启——11.3 runtime 可直接反序列化 11.2 plan（无重建、0.6s），
  但执行慢 ~12%；反之 11.2 runtime 加载 11.3 plan 也成功（MVC）。
  ⇒ **升级 TRT 必须删除引擎缓存强制原生重建**，否则"兼容加载"会把
  收益/损失都稀释成假数字。
- 回滚：F 盘 11.2.1.2 zip 内 cp313 wheel 重装（零网络依赖）+ 缓存
  换回 11.2 原生 plan；终态 p50 8.72ms ≈ 基线，e2e sanity 2735 段。

## 复评触发

TRT 11.4+/12 发布（kernel 显著换代）/ 换卡 / fp16 或 INT8 立项时。
