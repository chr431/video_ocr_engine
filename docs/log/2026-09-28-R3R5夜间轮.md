## R3-1 av1 hybrid 顺序读停滞（夜间轮最大意外，~2.5h）

开场状态：CPU 半边恢复网已提交（c17ce15），计划对称扩展到 GPU 侧。

**GPU 侧对称扩展尝试 → 回退**。把 `eof_pushed_ && s == SIDE_CPU` 的
侧限制去掉后：av1 hybrid_gpu stream 套件 ref 段 FATAL **3/5**
（对照：仅 CPU 半边同夜 16/16 绿——10× av1 复现器 + 6× stream）。
回退后（仅注释差异的重建）**同样 run1 即 FATAL**——失败率是**二进制
布局轮盘**（昨日 forensics 已知：v0.8.4 0/6、2b230be 0/6、修复版
~7/22），对称扩展不是根因但缺乏正确性证明，保守回退并留注释
（`src/video/hybrid/pump.cc` Pop 内 + `.h`）。

**取证过程（Heisenbug 全套）**：

| 实验 | 结果 |
|---|---|
| 默认预算（10240×1ms≈10.4s）stream 套件 | 4/6、3/4、1/1 FATAL（同签名：av1 hybrid_gpu ref 段，video_reader.cc:917） |
| 纯主线程 + 预算 30000（≈30s） | **3/3 过** |
| 纯主线程 + 预算 99999999 | **2/2 过** |
| HYBRID_DEBUG=1（任何预算） | 4/4 + 3/3 过（stderr 2 万行拖慢消费者） |
| 看门狗线程（读取放子线程，零 env） | 3/3 + 3/3 过（连 GIL 切换都避开竞态） |
| 单 reader 复现器（无套件前置） | 3/3 过——失败需要 hevc/h264/av1×gpu/hybrid 前置序列 |
| 失败运行诊断搜索 | `[pop-stall*]`/`[stale-drain]` **零打印**——Pop 的全部假返回路径已插桩仍零命中 |

结论：停滞为 **self-resolving**（>10.4s 自行恢复，非死锁），任何扰动
（打印/线程/序列变化）都改变时序窗口。机理旁证：健康运行消费 2000
帧时 `gpu_pkt_q=15182`（整文件 318MB 装进 512MB 包缓存 → demux 秒完
→ `eof_` 提前为真 → 万级已派包排空 10~30s）。静态 10240 预算为上游
为毫秒级尾排空所设，对该形态结构性偏小。

**修复（video_reader.cc NextFrameImpl，6569783）**：预算耗尽时先查
`decoder_->Drained()`——在途工作未清不宣判卡死，宽限至 10× 预算
（真死锁 ~104s 内仍 FATAL；纯 CPU/GPU 解码器真 EOF 时 Drained()=true，
行为不变）。**验证：stream 10/10 ALL PASS（默认预算）+ run_fast 六套件
全绿 + 健康运行 force_eof=0（恢复网零误触发）**。

附带：三条原零诊断路径补齐取证（pop-stall3 未派工头块 / pop-stall4
空队 fallthrough / stale-drain 陈旧排放计数），健康路径零成本。
取证器 `decord/tools/repro_av1_seq_stall.py`（v4，全相位+看门狗）。

**未解事项（诚实记录）**：停滞的精确微观机理（哪条互锁链吃了 10~30s）
未定位——所有插桩路径零命中意味着卡点在「Pop 返回 true + 未定义帧」
或消费者侧未观察到的形态；宽限修复是预算层兜底而非根因消除。
GPU 侧 marker 顺序竞态（昨日推断）亦未获直接证据。两者挂起待
下一轮带 minidump/内核级取证。
