# 2026-09-13 工作项 5：修 FORCE_SHARE 死旋钮 + 固化"换 DLL 交错 A/B"

## 一、死旋钮已修（fork）

**问题**（源码级）：`BuildPlan(key_pts, cpu_share)` 的分配循环只用 `rc`/`rg`：

```cpp
Side s = (static_cast<double>(ac) * rg <= static_cast<double>(ag) * rc)
             ? SIDE_CPU : SIDE_GPU;
```

形参 `cpu_share` 在 fork 源码里**只出现三次**（签名 / `.h` 声明 / 调试打印），
从未参与分配 ⇒ `DECORD_HYBRID_FORCE_SHARE` 是死旋钮。实测后果就是当时那次
份额扫描（0.02→0.35）扫到的全是噪声：wall 10.82~11.20s（±3.5%）、CPU 包数
6341~7561 基本不动 —— **"份额是否失当"这个假设当时无法用该旋钮检验**。

**修改**：把"按速率比水位"改写为**按份额水位**（两者代数等价，故默认不变）：

```
ac/(ac+ag) <= f   ⟺   ac*(1-f) <= ag*f          // f = cpu_share
```

`f` 由调用方给：默认 `rc/(rc+rg)`，`FORCE_SHARE` 覆盖时取覆盖值。

**验证**（`DECORD_HYBRID_DEBUG=1` 读 `[hybrid-plan]` 的 cpu/gpu chunk 数）：

| 运行 | cpu/gpu chunks | CPU 占比 | 目标 |
|---|---|---|---|
| 默认 | 29 / 67 | 30.2% | 随速率估计（≈0.29） |
| `FORCE_SHARE=0.10` | 9 / 87 | **9.4%** | 10% |
| `FORCE_SHARE=0.60` | 59 / 37 | **61.5%** | 60% |

DLL md5 `6367c5fa…` → `1e918fa4…`；金标 `record.py --verify` **28/28**。

## 二、换 DLL 的交错 A/B 已固化（新增 `tools/_probe_dll_ab.py`）

**为什么不能复用 `bench ab`**：`bench._round` 是**同进程内**直接构造
`FieldExtractor` 并 `extract()`，而 DLL 一旦加载无法替换 ⇒ 换 DLL 的 A/B
**必须每臂一个新进程**。本探针补的正是这个缺口。

实现要点：逐轮交错 + **每轮轮转先后**（拉丁方）；每臂跑前把所选变体拷成
`<dir>\decord.dll` 并**校验 md5**；子进程以 `DECORD_LIBRARY_PATH=<dir>` 运行；
统计量 = 同轮配对差分**均值** + SE，另需**符号多数一致**（≥70%）；可分辨下限取
`bench.PI15_LIMITS["std_pct"]`（0.30%）。

**首跑即用**：A = 份额重构前的 DLL（`6367c5fa…`）、B = 重构后（`1e918fa4…`），
hevc-hybrid / 3000 帧 / rounds=4 / inner=2：

| 轮 | A | B | 差分(B−A) |
|---|---|---|---|
| r00 | 2.1002 | 2.0339 | −3.16% |
| r01 | 2.1408 | 2.0789 | −2.89% |
| r02 | 1.9913 | 2.1087 | +5.90% |
| r03 | 1.9943 | 2.0642 | +3.50% |

均值 **+0.837%**、sd 4.567%、SE 2.283%、符号 2正/2负 ⇒ **判定：噪声内** —— 与
"两种水位代数等价、默认分配不变"的预期一致（这是**等价性检查**，不是性能主张）。

### ⚠️ 噪声带：比同进程 `bench ab` 大一个量级（必须记下来）
| harness | 每臂 | 配对差分 sd | 判 1% 级效应所需 |
|---|---|---|---|
| `bench ab`（同进程，inner=3） | 热池复用 | ≈0.5% | n=25 已足 |
| `_probe_dll_ab.py`（每臂新进程） | **冷启动** | **4.6%** | **≥20 轮** |

⇒ 用法约定：判 **≥5%** 的效应用 4 轮即可；判 **1% 级** 需 ≥20 轮；判
**等价性**（"没改坏"）只需看是否落在噪声内。

### 一个已修的坑（留档）
首版探针**结束后不恢复** `decord.dll`，于是目标停留在"最后一个臂"的 DLL 上
（该轮末臂是 A ⇒ 我随后一次 goldens 复核**误验了旧 DLL**）。现改为：实验开始
即把目标另存 `.pre-ab`，默认结束后恢复；`--keep-last` 可显式关闭。
