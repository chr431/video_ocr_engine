# 2026-10-09 周期计数测量首轮：CPU 周期账本 + GPU 指令账本

> 动机：项目自诞生起饱受机器性能漂移/后台负载干扰，墙钟数字只能靠
> 多次重复压误差。上轮分析（未落码）提出直接测"计算量"替代墙钟：
> CPU 用 QueryProcessCycleTime（进程全线程 TSC 周期，只计在 CPU 上
> 运行的时间），GPU 用 sm__inst_executed（NVIDIA 硬件指令计数器）。
> 本轮用户授权实验（"开始实验基于周期计数的性能测量方式"，UAC 静默
> 允许提权直取 ncu）。判据面结论见 C-63；本文只叙事。

## 1. 工具与提权路径

- **CPU**：`tools/_probe_cycle_ledger.py`——ctypes 直调
  `QueryProcessCycleTime(GetCurrentProcess())`，粒度即 TSC（对照
  GetProcessTimes 的 15.6ms 量子）。负载轴用 spawn 子进程自旋组
  （独立进程，只抢 CPU 不进账本）。
- **GPU**：`tools/_probe_gpu_inst.py`——确定性负载 = 引擎自带 NVRTC
  kernel（`GpuFrameAnalyzer.analyze_batch`，memset 常量输入 B×1080×1920，
  预热臂 B=8 按 grid 与正式臂 B=64 在 CSV 里区分）；指令计数用 Nsight
  Compute 2026.2.0（本机已装），GeForce 上需管理员令牌——Windows sudo
  被禁用，实测 `Start-Process -Verb RunAs`（UAC 静默）+ cmd 重定向
  出文件可行（`net session` 验证令牌为管理员）。ncu 无 `--eula-accepted`
  选项，本机已接受过 EULA，未触发交互。

### 工程教训：自旋负载子进程不能用 `Event.is_set()` 做停止条件

`while not stop.is_set(): pass` 实测每子进程只烧 ~20% LP（4 个"自旋"
整机 busy 仅 18%）——`is_set()` 走 Condition 锁（Windows 信号量
acquire），~80% 时间阻塞在等待里。改 `while True: pass` + `terminate()`
收尾后满烧（1.50s CPU / 1.50s 墙钟）。后续任何探针要造 CPU 负载都别
再踩。

## 2. CPU 周期账本结果

合成负载（固定种子 512³ 矩阵乘 ×200 + 1M 纯 Python 循环，预热后 8 reps）：

| load | wall | wall CV | cycles | cycles CV | cycles/idle |
|---|---|---|---|---|---|
| 0 | 138ms | 5.05% | 3.169G | 1.25% | 1.000 |
| 8 | 148ms | 1.25% | 3.569G | 1.21% | 1.126 |
| 32 | 930ms | 45.61% | 7.586G | 27.49% | **2.394** |

矩阵乘是**反面教材**：满载时 OpenBLAS 自旋等待线程把周期账本污染
+139%——周期数计的是"线程时间×TSC"，进程内自旋照计。BLAS 密集型
负载满载下账本不可用。

引擎真实负载（test5.mp4 600 帧 stride=1，FieldExtractor 构造计入，
cpu 解码 + OpenVINO OCR，每臂预热 1 次后 8 reps）：

| 臂 | load | wall | wall CV | cycles | cycles CV | cycles/idle |
|---|---|---|---|---|---|---|
| cpu | 0 | 449ms | 0.94% | 16.350G | 0.97% | 1.000 |
| cpu | 8 | 497ms | 2.53% | 18.913G | 2.28% | 1.157 |
| cpu | 32 | 4635ms | 36.22% | 13.953G | **0.67%** | 0.853 |
| nvdec | 0 | 695ms | 0.76% | 5.912G | 1.16% | 1.000 |
| nvdec | 32 | 5582ms | 30.10% | 5.706G | **2.03%** | **0.965** |

引擎栈（decord + OpenVINO/TBB，无自旋放大）下：满载墙钟被拉伸
8-10×、CV 30-36%，而周期 CV ≤2.3%、跨负载均值守恒在 0.85-0.97×
（nvdec 臂 0.965 近乎完美；cpu 臂 0.853 的 −15% 方向为"饱和时线程
并行 overshoot 减少"，未深究）。区分度：cpu 16.35G vs nvdec 5.91G
（2.8×）远超噪声。原始逐 rep 记录在 `bench/cycle_ledger_engine.log`
（本地）。

## 3. GPU 指令账本结果（ncu）

三次提权采集（idle×2 + load32×1，各 8 次正式 launch），
`--metrics sm__inst_executed.sum,gpu__time_duration.sum,launch__grid_size`：

- 24 次 grid=64 launch：min 721,355,456 / max 721,357,419，
  **相对散布 2.72e-6**；三离散峰（N≈721,356,4xx±11、N−987、N+982），
  离散双峰说明 kernel 存在极轻微数据相关分支（输入为 memset 常量，
  疑似未初始化读，未归因）；load32 下低峰模式占 5/8、idle 下 0-1/8
  ——负载与模式选择相关，机制未查。
- 同负载纯墙钟对照（ncu 外）：idle 8.42ms CV 4.72% / load32
  8.60ms CV 2.29%；ncu 锁频下 gpu__time_duration ≈7.77ms。
- 工作量线性自检：grid=8 → 90,169,557 inst，grid=64 → 721.36M
  ≈ 8.0× ✓。
- CSV 存 `bench/gpu_inst_{idle1,idle2,load32}.csv`（本地）。

分辨率对比：指令账本散布 2.7e-6 vs 墙钟 CV 2-5%——三个数量级。
GPU 侧代码变更比较 n=1 次采集即可分辨 0.01% 级差异，且不受频率
漂移/调度影响。代价：ncu 重放扰动执行时序 + 需管理员，只能离线
专用模式，不可作 in-process 遥测。

## 4. 边界与未做

- SMT 争用使周期**均值**移动 ±16% 带（cpu 臂 0.853-1.157）——交错
  协议不能省，周期数的价值是同条件分辨率与跨频稳定，不是免交错。
- BLAS/OpenMP 自旋库满载 +139%：账本对"进程内自旋"不免疫。
- GPU 指令三峰离散与负载相关模式偏移未归因（量级 1.4e-6，不影响
  判据使用；追因需 CUPTI PC 采样，留待需要时）。
- 未做：bench 集成为判据（需先按 C-63 前提实战一轮 A/B）；in-process
  CUPTI（cuda-python 13.x 无 cupti 绑定，ctypes 面 = range profiler +
  NVPW 两大 API，收益/成本比不过离线 ncu）；NVDEC 工作量无周期面，
  现行帧计数（frames_c/frames_g）即其工作量度量。
