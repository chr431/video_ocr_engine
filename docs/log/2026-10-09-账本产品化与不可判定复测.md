# 2026-10-09 周期账本产品化与不可判定复测

> 上轮（周期计数测量首轮）以探针验证了账本判据的可行性（C-63）。本轮
> 用户裁决"全量实现，完成后复测之前测量分辨率下认为无法分辨的改进"：
> 把 CPU 周期账本接进 RunReport 与 `bench ab`，然后复测两个当时判
> "不可判定"的结论——C-50（DECODE_THREADS）与 C-47（TRT_DEFER_SYNC
> e2e 平价）。判据面结论见 C-64；本文只叙事。

## 1. 产品化（report v7 + bench 判读）

发现：`video_ocr_engine/domain/resources.py` 自 P2a（2026-09-17）起就在每个 L1 边界采
`QueryProcessCycleTime`，但 `per_phase()` 把 cycles 换算成
`cores_avg_cycles`（÷墙钟 ÷全程频率）后**丢弃了原始差分**——判据用的
本体一直没透出。本轮实现因此极薄：

- `ResourceProbe.per_phase()` 行新增原始 `cycles` 差分 + `cycles_e2e`
  （末边界−首边界，覆盖 calibrate+decode+ocr；零新增采样调用）。
- `REPORT_VERSION` 6→7（只加键；cycles 来源缺席=非 Windows 时无键）。
- `bench.py`：`_flatten` 提取 `cyc:<phase>`/`cyc:e2e` 进逐指标归因表；
  新增 `_cycle_verdict`——与 wall 判定同款纪律（|均值|>3×SE ∧ 符号多数
  ≥70%）的周期判读，**只判读不改退出码**（wall 仍是唯一失败判据）。
- 测试：版本钉 ×2 处更新、per_phase cycles 断言（win32）、
  `tests/test_bench_cycles.py`（flatten 提取/判读门槛/噪声不可判定/
  缺席静默）。全量 pytest 283 绿、mypy 绿、遥测成本守卫绿（零新增调用）。

GPU 指令侧维持探针载体（`_probe_gpu_inst.py`，ncu 需管理员+重放扰动，
天然离线），不进产品路径——这是有意的设计边界，不是未完成。

## 2. A/A 标定（h264-cpu，n=6 对，window 600，--no-clock-gate）

cpu 配置下 GPU 空闲，SM 时钟门禁会把全部热轮误剔（本机实测"无热轮"）
——CPU 臂一律 `--no-clock-gate`（`_gpu_valid` 对 gate=off 记 True）。

| 键 | Δ均值 | SE | 可分辨下限（|μ|+3SE） |
|---|---|---|---|
| cyc:e2e | +0.33% | 0.41% | **1.58%** |
| cyc:decode | +1.13% | 0.50% | 2.62% |
| 墙钟 | +0.28% | 0.85% | 2.85% |

同批同 n：周期账本比墙钟分辨力高 ~1.8×（安静态）；满载下的差距见
C-63（30-36% vs ≤2.3%）。n=16 配对（repeat 8 × rounds 3）时周期
SE 收到 0.4-0.7%。

## 3. 复测一：C-50 DECODE_THREADS（2026-09-17 判 +0.97% 不可判定）

口径对齐花了两个 round：bench 默认 `--ocr-backend tensorrt`（GPU-OCR
口径）下 auto=32——首轮 d10 vs d32 实测 d32 墙钟 −27%/周期 +44.5%，
即 **auto 分档表在 GPU-OCR 口径已最优**（压到 10 反而墙钟 +37%）。
C-50 原口径是 CPU-OCR（auto=10），复测用 `--ocr-backend cpu`：

- **墙钟**（n=16 配对）：d32 **−1.86%±0.38%（14/16 负号）**——旧分辨率
  （+0.97%±2.23%）不可判定的差异，现在 CI 排零 ∧ 符号多数成立。
- **周期账本**：decode 相位 **−16.36%**（0/16，解码本体更省）但 e2e
  **+13.37%**（16/16）、ocr 相位 +272.9%（16/16）——争用税全落在
  decode 之外（OV 线程被 32 解码线程挤压）。

处置：**维持 auto=10（CPU-OCR 口径）**——−2% 墙钟换 +13% CPU 在共享
桌面不值（C-08 稳妥哲学同向）；「GIL 对冲」从假设变成量化签名
（e2e 周期 +13.4% 就是那个"对冲"的本体）。复评触发新增"独占部署"。

## 4. 复测二：C-47 TRT_DEFER_SYNC e2e（2026-09-17 判 +0.167%±0.144% 不可判定）

h264-gpu（nvdec+TRT，时钟门禁开），n=16 配对：

- **墙钟**：+0.334%±0.317%（10/16）——平价复确认，与 C-47 的
  +0.167%±0.144% 一致。
- **周期账本**：e2e **+4.60%**（16/16）、decode 相位 +5.48%（15/16）——
  deferred collection 的宿主开销第一次可分辨。e2e 平价是因为该开销
  藏在 GPU 等待的阴影里；C-47 复评触发（"GPU 链争用减"）兑现时，
  这 +4.6% 可能浮出为墙钟。

## 5. 遗留

- `bench ab --aa` 分支在周期判读前 `continue`——A/A 周期带须从 registry
  事后算（本轮即如此）；如后续常用可补一行。
- 归因表 cyc:ocr/cyc:calibrate 的 A/A 带很宽（27%/8.6%）——小相位样本
  少，判读以 cyc:e2e/cyc:decode 为主。
- 版本 0.19.0（report schema v7）。
