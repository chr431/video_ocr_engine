# 第一性审查轮（全仓生产代码 / 常备探针 / 测试套件）

审查对象：`video_ocr_engine/` 全部 44 个模块（12,055 行）、`tools/` 守卫与 live 探针、`tests/` 全量（41 文件 5,620 行）。方法：按"每个子系统的不可约职责是什么 → 实现是否超出该职责 → 失败是否静默"三问逐区审查，7 路并行子代理分区（config / OCR / decode / GPU 设备层 / domain 算法 / 测试 / 探针守卫）+ 全仓交叉面（死代码、异常处理普查、跨模块私有访问、同名定义、重复字面量）由人工完成；子代理结论全部经人工逐行复核后才采信，复核中被推翻的（如 GPU prev 帧自拷贝疑点）不列入。本文记录发现与修复过程；结论一行见 `docs/CONCLUSIONS.md` C-80。

## §1 P0——会给出错误保证或静默错误结果

### 1.1 发版清扫守卫永不失败，输出被丢弃

`tools/check.py:60-61` 注册 sweep 步未带 `--strict`；`tools/conclusions_sweep.py:128-129` 只在 `--strict` 下返回 1；`tools/check.py:96-98` 只在步骤失败时打印其输出。实测 `python tools/conclusions_sweep.py --strict` 退出码 1，列出 11 条落后钉版（C-05、C-31、C-32、C-49、C-62、C-66、C-68、C-69、C-72、C-74、C-75，另 C-76 三行），而 `check.py --tier release` 同日仍报「✓ release 链全部通过」。次要：`tools/check.py:92-94` 把 SKIP 计入通过，无视频语料的机器上金标步被跳过后汇总仍报全通过。

### 1.2 硬编码路径审计的正则抓不到引号内字面量

`tools/env_doctor.py:37` 负向后顾 `(?<![\w"'#])` 排除了前导引号，而 Python 路径字面量必然在引号内。实测（import 该模块正则直接验证）：`'VIDS = r"D:\Videos\..."'` 不匹配；语法非法的裸形式匹配。`env_doctor.py --audit` 报「✓ 无硬编码绝对路径」，同树 `tests/golden/bench_baseline.py:21-23` 有三处 `r"D:\Videos\racelog_test\..."`；`tests/test_discipline.py:56` 断言该审计退出 0。该正则与审计项同为 2026-09-19 纪律轮引入（git 86507aa）。

### 1.3 六个 env-live 旋钮的显式 override 静默无效，config_digest 对其不可区分

`video_ocr_engine/config/knobs.py` 标 `env_live_only=True` 的六个旋钮（`ocr.trt_fp16` / `ocr.trt_defer_sync` / `pipeline.gpu_stream` / `pipeline.gpu_drainer` / `diag.subprobe` / `diag.bounds_debug`）由消费者调用期直读 env（`video_ocr_engine/ocr/trt.py:88`、`video_ocr_engine/gpu/streams.py:288,305`、`video_ocr_engine/ocr/trt.py:31`、`video_ocr_engine/domain/segmentation.py:312`），RunConfig 字段无人读取。两项实测：

- `resolve(env={}, overrides={"ocr.trt_fp16": True}).ocr_trt_fp16` 为 True，而 `trt._fp16_on()` 读 env 为 False——显式参数静默无效，与 `resolve.py:3` 与 README「显式构造参数 > env > 默认」的优先级承诺相悖。
- `config_digest` 在 `TRT_FP16=0/1` 与 `TRT_DEFER_SYNC=0/1` 下完全相同（实测均为 `f2f6e6dc9c6cc3a1`）；`run_config.py` 自述该指纹「覆盖全部生效值…供 A/B 对账」。

另：`video_ocr_engine/ocr/trt.py:31` 的 `SUBPROBE_ON` 为模块导入期读取，导入后不可变更，与其旋钮条目「v2 统一构造期一次」的备注不符。

### 1.4 test_warmup 把真实缺陷转成 skip，PI-10 门禁未在标准链跑过

`tests/pipeline/test_warmup.py:84-88` 的 try 同时包住 `warmup()`、`extract()` 与 `meta["report"]` 访问，异常一律 `pytest.skip("TRT/引擎不可用")`。实际跳因 `KeyError('report')`：遥测默认 off（`video_ocr_engine/config/run_config.py:43`），报告只在非空时挂上（`video_ocr_engine/extractor.py:551-552`）。设置 `VOE_TELEMETRY=full` 后该测试通过（子代理实测）。

## §2 P1——不可靠：静默丢数、热路径失败不可见

### 2.1 CUDA 内核层错误返回弃置，热路径失败变成垃圾测量值

`video_ocr_engine/_gpu_kernels.py:1311` 分配 `_summary_dev` 不检查错误；`:1326` 以 `np.empty((B,2))` 接收 D2H，`:1327-1334` 拷贝与同步返回码全弃——`analyze_batch` 可返回未初始化内存，其值即分段的 sharp/cluster。同形：`compare_pair`（`:1292` `np.empty(3)`，返回值驱动合并判定）、`content_range`/`content_range_batch`/`luma_into_batch`、五个 `_ensure_*`（`:245-303`，唯一守卫是 `python -O` 下消失的 assert）。对照 `video_ocr_engine/gpu/pools.py:104-109` 已有正确范式（查 err、抛 MemoryError，注释记载此前丢弃 _err 被专项修过）。

### 2.2 直方图分箱边界整表偏 2×

`video_ocr_engine/domain/metrics.py:53-55` 以 `2**(i-20)` 造下界表，`hist_bucket`（`:62`）用 frexp 指数+bias 定桶——`LOWER[i]` 实为该桶上界。实测 `x=0.5`→桶 20 而 `LOWER[20]=1.0`；`x=1.0`→桶 21 而 `LOWER[21]=2.0`。`report.py:293-295` 将该表作为权威发布并注明「桶 i 覆盖 [lower[i], lower[i+1])」。

### 2.3 二十处 try/except 包裸 cudart 调用，异常分支永不触发

cuda-python runtime 绑定返回 `(err, ...)` 元组不抛异常（本仓他处即按元组解包），故 `try: cudart.cudaStreamSynchronize(s) except Exception: pass` 的 except 为死代码。全仓 20 处（`video_ocr_engine/_gpu_kernels.py` 9、`video_ocr_engine/gpu/pools.py` 6、`video_ocr_engine/ocr/trt.py` 5），含 `pools.py:135,154` 放弃路径 `cudaFree`（失败=静默泄漏）。

### 2.4 双 OCR 车道预处理 gamma 不同源

`video_ocr_engine/ocr/native.py:117` 车道 prep 写死 `gamma=None`，`video_ocr_engine/_gpu_kernels.py:398-401` 对 None 的语义是逐批重读 `OCR_GAMMA`；宿主路径用冻结 `spec.gamma`（`ocr_stage.py:713,725`），引擎自带 prep 用冻结 `self._gamma`（`native.py:456`）。env 中途变更或经 overrides 构造时，同一帧因车道归属不同而得到不同预处理。

### 2.5 `crop_is_expected` 为假被当「全帧」静默错切

`video_ocr_engine/decode/decord_source.py:371-375` 为纯形状判据；`video_ocr_engine/pipeline/host_backend.py:116-117,128-129` 在其为假时用全帧坐标切已 ROI 裁剪的数组。生产恒传 roi（`ensure_roi_capable_decoder` 构造期硬校验），False 只可能意味着布局契约破坏，现走静默切片、无降级记录、无异常。

### 2.6 `_cluster_win3` 对任意 dtype 做 uint8 重解释

`video_ocr_engine/domain/segmentation.py:153-154` `diff.view(np.uint8)` 仅对 bool 成立；宿主与 GPU 共用判定原语，若传入 float32 差分将得到原始字节图案（分数恒≥C → 逐帧断段）。现两调用点均传 bool，属潜伏。

### 2.7 gauges 合并按「最后写入者胜」，赢家=线程注册顺序

`video_ocr_engine/domain/metrics.py:478-479` 逐桶 `gauges[k] = v`，桶序=线程首触顺序；`*_max` 型 gauge 较大观测可被丢弃。最大值本体在 `video_ocr_engine/domain/prof.py:84-92` 由 producer 与各 infer 线程对普通 dict 无锁读改写（totals 累加同）。

### 2.8 纪律审计 baseline 含 23 处被动余量

`tools/_probe_discipline_audit.py:602-608`（`--update-baseline`）统计全部 `except: pass`，检查器（`:252-260`）先豁免带注释者再与 baseline 比对，allowed 恒≥可报数。实测：`video_ocr_engine/gpu/device.py` 允许 5 而全文件无 `pass`；`video_ocr_engine/pipeline/host_backend.py` 允许 5 而其裸 `pass` 是 lane 空方法、不在 except 内。

## §7 复核中被推翻的疑点（存档防重查）

- GPU prev 帧「自拷贝」疑点：`streams.py:255/279` 两次 `_ensure_prev` 因只增分配返回同址，yuv 路径 `first_src==prev_buf` 的拷贝确为同址——但其语义即「保留上一批末帧在 prev_buf[0]」，同址拷贝为有意设计，B 为批尺寸常量上界故无重分配悬垂；降级为记录不修。
- `_driver.py:196` `results[i]` 缺键风险：err 路径先在 `:184` 抛 RuntimeError，defer 路径逐批提交/收集平衡，缺键表现为 KeyError（响亮）而非静默错文本；降级为记录。
- OCR `results` 字典跨线程写：键互异、GIL 下 dict 单键写原子，无竞争。
- `video_ocr_engine/_gpu_kernels.py` `_KERNEL_MODULE_CACHE` 无锁：dict 单操作原子，最坏双编译（幂等），不改。
