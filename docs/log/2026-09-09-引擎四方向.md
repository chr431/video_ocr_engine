# 2026-09-09 引擎四方向：可插拔化 / 性能画像 / 冗余清理 / 架构图

> 叙事。规范性结论见 `docs/CONCLUSIONS.md` C-31/C-32。

## 方向1：预处理/分段/裁切统一实现（原"可插拔化"方案的翻案）

第一版做成了插件注册表（模块 _stages.py：Segmenter/Preprocessor 协议 + 注册表
+ 模型注册表 + 构造参数 segmenter=/preprocessor=/ocr_model=），带门控：
插件激活时 GPU 全驻留管线让位宿主管线。真值与测试全绿后判定方向错误：
**GPU 管线的分段/裁切/预处理是设备侧 kernel 实现，插件语义无法进入**，
"插件激活即降速到宿主管线"等于把默认快路径对插件用户关闭——抽象面与
识别链架构冲突，该模块已删除、改动已整体回退（注册表、钩子、门控、测试）。

改为**统一两侧实现为一个文件**：`segmentation.py` 成为分段+预处理的
唯一实现地（C-32）——

- §1 像素原语（原有）：批量灰度/g_buf 复用、NV12 Y 展开、Otsu（帧 +
  直方图两口径）、win3 聚类（uint8 零拷贝）。
- §2 校准与判定（收编 `_helpers`/extractor）：otsu_median_threshold、
  similar_decision（两阈值判据，宿主 numpy 统计与 GPU sim_pair 标量
  共用）、similar_binary（binary 分离 + int16 精确差宿主实现）。
- §3 SegmentStateMachine（收编两侧同构状态机）：断段/代表帧(std)/合并
  统一编排；宿主喂 bin（win3 本机算），GPU 喂 cluster 分数（kernel 已算）；
  emit/similar/取消/进度为回调，节拍（100/500 帧）与边界打印语义不变。
- §4 裁切与预处理（收编 mixin）：content_range_to_crop（余量+最小收益
  门槛数学）、crop_to_content / crop_after_aspect（顺序⑦）、
  preprocess_standard（自 video_utils 移入，原位置转发兼容）。

GPU 侧 CUDA kernel 保持设备侧逐位镜像（像素操作无法跨 numpy/CUDA 共享），
但判定阈值/余量数学/合并判据全部引用 segmentation.py —— 两侧语义只有
一个出处，无插件抽象面。`_helpers`/`video_utils` 旧入口保留转发（探针
与测试引用面不动）。

## 方向2：性能画像与候选验证（先量后做，两项否决）

ENGINE_PROFILE 画像（test6 3000 帧）：

- 默认 GPU 管线（热引擎）：wall 2.07s = 解码 1.77s（NVDEC 硬件边界）+
  尾排空；OCR 线程 q_get_wait 1.91s（等料）→ **解码受限，已充分重叠**。
- host_cpu：wall 4.4s，ONNX infer 8.1s（与解码 3.9s 重叠后 OCR 受限）。

候选实验（均无收益，默认值维持）：

| 候选 | 结果 |
|---|---|
| OCR 重排窗口 16/32/64 | wall 2.054/2.078/2.081s，噪声级；put_block 不转化为墙钟 |
| OCR_BATCH 16/32/64（host_cpu） | wall 4.40/4.61/4.74s，默认 16 已最优 |

有效提升仍属上一轮的 av1 线程策略（C-31）。剩余墙钟 = 解码供给
（NVDEC 硬件/线程策略已到顶）+ 打开器 0.11-0.17s + 尾批排空；
hybrid（已有）是 av1/hevc 全片场景的现成杠杆。

## 方向3：冗余清理

- 删除（均无任何文档/代码引用、从未入库）：`index/`（前 v2.13 重 OCR
  时代的 idx 缓存残留）、`PERFORMACE_REPORT.txt`（旧只读审查报告，引用
  已删除的 hybrid_decode.py，性质是历史快照，不作现用文档）。
- 过期注释修正：fork `DECORD_FFMPEG_THREAD_COUNT` 口径两处
  （clamp(hw/4,2,8) → 0.8.x 实为 clamp(hw/2,2,16) 且随 fork 版本变化，
  引擎全路径显式传线程不依赖该默认）；extractor 模块 docstring 的
  "hybrid 由顶层 hybrid_decode.py 承担"（该文件已删，hybrid 为 decord 原生）。
- `OCR_PAD_WIDTH_MIN_BY_MODEL` 在引擎内被注册表取代（探针仍引用，常量
  保留，语义标注待两版本后清理）。
