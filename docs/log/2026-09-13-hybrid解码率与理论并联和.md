# 2026-09-13 hybrid 解码率 vs 两解码器理论并联和（第一笔）

## 口径
- 三编码为**同内容族**（test6 三件套），ROI 一致（841,994,949,1026），3000 帧。
- 消费端统一 `ocr=trt`，以**隔离解码**（TRT 几乎不吃 host CPU，避免 CPU OCR 与
  CPU 解码抢核污染对照）。
- 指标取 `pipeline.decode` 的 span sum；单臂各跑一次（**非 A/B**）。
- 命令：`SURVEY_FRAMES=3000 SURVEY_CONFIGS=cpu/trt,nvdec/trt,hybrid/trt
  python tools/_probe_path_survey.py`

## 数据
| 编码 | cpu/trt decode | nvdec/trt | hybrid/trt | 理论并联和 | 并联效率 |
|---|---|---|---|---|---|
| h264 | 1.418s（2116 fps） | 3.208s（935 fps） | 1.716s（1748 fps） | 3051 fps | **57.3%** |
| hevc | 3.438s（873 fps） | 1.520s（1974 fps） | 1.598s（1877 fps） | 2847 fps | **65.9%** |
| av1 | 2.460s（1220 fps） | 1.809s（1658 fps） | 1.514s（1982 fps） | 2878 fps | **68.9%** |

（理论并联和 = 两单臂速率直接相加；并联效率 = hybrid 实测 ÷ 理论并联和。）

## 三条读法
1. **并联效率只有 57–69%**：hybrid 拿到两解码器理想和的约三分之二，调度效率
   仍有空间（与 C-39 记的"调度器达混跑理想 94–97%"口径不同，那条是**混跑份额
   兑现率**，本条是**速率相对理论并联和**，两者不可互换）。
2. **h264 上 hybrid 输给单臂 CPU**：1748 vs 2116 fps（−17%）。而 NVDEC 在 h264
   上是硬件天花板（935 fps，C-04 记 982 fps 同级）——故 h264 的"混合"实际是在
   用一条明显更慢的腿拖累一条更快的腿。这与 C-08 记的"h264 CPU 软解快 1.7–2.8×"
   以及本仓路径普查里 `cpu/trt` 优于 `nvdec/trt` 一致。
3. hevc 上 hybrid（1877）也略输纯 NVDEC（1974，−5%）；只有 av1 上 hybrid 反超
   纯 NVDEC（1982 vs 1658，+20%）。**"混合必然更快"不成立，方向随 codec 变。**

## 修正与本轮归因（同日续）

### ⚠️ 更正一：上一节的"h264 hybrid 输给单臂 CPU −17%"被交错 A/B **否决**
交错 A/B（`h264same-nvdec`，3000 帧，ocr=trt，repeat 3）：

| 对照 | A 热池 | B 热池 | Δ% | 符号 |
|---|---|---|---|---|
| h264：cpu → hybrid | 1.6212 | **1.5842** | **−2.28%** | `---` |
| hevc：nvdec → hybrid | **1.5917** | 1.6656 | **+4.64%** | `+++` |
| av1：nvdec → hybrid | 1.8751 | **1.4726** | **−21.47%** | `---` |

**错因**：上一节拿**单臂的 `pipeline.decode` span** 做跨臂比较，但 cpu 臂的
decode 只占其墙钟 67%（1.418/2.117s）——span 对比不等于端到端对比，
"理论并联和"那套算法因此失真。

### ⚠️ 更正二：全片口径下 hybrid 在**三编码上全部优于纯 NVDEC**
`tools/_probe_hybrid_reeval.py`（`DECORD_FORK_BUILD=D:\Repo\decord\build-081fix`，
全片、两轮）：

| 编码 | nvdec | hybrid | Δ |
|---|---|---|---|
| h264（2735 段） | 8.78 / 8.71s | 3.83 / 3.87s | **−55.9%** |
| hevc（8340 段） | 12.69 / 12.78s | 10.62 / 10.96s | **−14.2%** |
| av1（8340 段） | 15.23 / 15.24s | 10.32 / 10.71s | **−29.7%** |

**与上一节 3000 帧窗口 A/B 的 hevc 结论相反**（窗口：nvdec 快 4.6%；全片：hybrid
快 14.2%）。换算速率可见端倪：窗口下 hybrid hevc ≈1801 fps，全片 ≈2187 fps
——即 **hybrid 的速率随运行长度改善**，3000 帧窗口摊销不掉启动期。
