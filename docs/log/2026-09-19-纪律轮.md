# 2026-09-19 纪律轮：环境事实源 + DLL 部署自动化（根除"找不到 ffmpeg / DLL 非最新"）

> 任务（用户）：此前多次发生找不到 ffmpeg、实际使用的 decord dll 非最新等问题，
> 设计一个方法根除。

## 1. 问题结构（为什么反复发生）

两类事故的**共同结构**：**「应该用哪个」的事实散落在多处，而「实际用了哪个」
从不校验**。

| 事故 | 现状（本轮审计实测） |
|---|---|
| 找不到 ffmpeg | **4 处硬编码路径**，其中 **3 处指向已不存在的 `D:\Software\ffmpeg8`**（目录早改名）；另有 1 处指向上一轮的临时目录 |
| DLL 非最新 | 构建产物 → site-packages 靠**手工 `cp`**；改了 C++ 忘了部署 = 测量静默用旧 DLL；`rebuild_dev.bat` 的 `CMAKE_BUILD_TYPE` 在 Debug/Release 间**反复漂移**（上一轮刚改 Release，本轮又见 Debug） |

**为什么审计没抓到**：既有纪律审计的检查 1「硬编码绝对路径」有两处盲区——
① 正则只匹配 `Repo|Users` 开头（`D:\Software\...` 不匹配）；
② **`tools/` 整体豁免**（理由"探针是一次性工具"）——而失效的 ffmpeg 路径
恰恰全在 tools/。

## 2. 根治设计（四层）

### 2.1 单一解析源：`tools/env_probe.py`

外部依赖路径**只在这里解析**：env 覆盖 → 候选列表依次探测。解析结果带
`source`（来自 env / 哪个候选目录）+ 版本 + md5，可打印、可断言。

```python
from env_probe import ffmpeg_bin          # 唯一获取方式
FFMPEG = str(ffmpeg_bin("ffmpeg"))        # 找不到 → FileNotFoundError
                                          # 并列出全部已探测候选
```

设计原则：**不引入新旋钮**（复用既有 `FFMPEG_DIR`）；**找不到就显式失败并
列出候选**，绝不静默回落。

### 2.2 显式校验：`tools/env_doctor.py`

```
python tools/env_doctor.py            # 体检：每个依赖的来源+版本+md5
python tools/env_doctor.py --deploy   # 构建产物 → site-packages（md5 校验）
python tools/env_doctor.py --audit    # 硬编码路径审计
python tools/env_doctor.py --json     # 供 CI/审计消费
```

**`--deploy` 是「DLL 非最新」的根治点**：md5 一致则跳过，不一致则同步并
**复验拷贝后的 md5**。

⚠️ 实现要点（本轮踩到并修正）：`--deploy` 必须用
`importlib.util.find_spec` 定位 decord，**不能 `import decord`**——import 会把
`decord.dll` 载入本进程并锁住，随后的覆盖必然失败（实测"目标 DLL 被占用"）。

### 2.3 构建+部署一体：`rebuild_dev.bat`

```bat
cmake -B build-081fix -DCMAKE_BUILD_TYPE=%CMAKE_BUILD_TYPE% ...   rem 显式、可覆盖
cmake --build build-081fix --parallel %*
taskkill /F /IM python.exe            rem 释放 DLL 占用
"%PYEXE%" tools\env_doctor.py --deploy   rem md5 校验 + 同步
```

**部署不再是独立的手工步骤**——忘记部署在物理上不可能（构建即部署）。

### 2.4 审计守门：纪律审计检查 1 升级 + 新增检查 13

- **检查 1 升级**：委托 `env_doctor --audit`，判据改为
  「任意盘符绝对路径字面量（docstring/注释/env 默认值豁免），**tools/ 不再
  整体豁免**」。升级后立刻抓出并修掉 4 处失效路径。
- **检查 13 新增**「外部依赖与 DLL 部署一致性」：
  - ffmpeg 可解析（含版本）；
  - **有 fork 构建产物时，其 md5 必须与已部署 DLL 一致**（不一致 = 改了
    C++ 没部署）；
  - 判据刻意区分「**装了但不一致**」（缺陷，判红）与「**没装**」（环境事实，
    仅警告）——CI 只装引擎依赖，把"缺外部工具"判红会让 CI 永久失败。

## 3. 反向对照（防假绿）

新检查必须证明**能抓到已知问题**，否则等于没有：

| 对照 | 结果 |
|---|---|
| 篡改已部署 `decord.dll`（追加 1 字节） | 检查 13 **立即判红**（md5 不一致）；恢复后通过 |
| 修复前的 4 处失效 ffmpeg 路径 | 升级后的检查 1 **全部抓出**（修复前是静默的） |
| `--deploy` 首次运行 | 实测暴露「DLL 被占用」缺陷 → 改 `find_spec` → 通过 |

## 5. 使用约定（写进 AGENTS.md）

1. 外部依赖路径**一律** `from env_probe import ffmpeg_bin`（或
   `os.environ.get` 带默认值）——**不得写绝对路径字面量**（审计检查 1 守门）；
2. 改完 decord C++ **跑 `rebuild_dev.bat`**（构建即部署，md5 自动校验）；
3. 环境异常先跑 `python tools/env_doctor.py`——它直接告诉你"每个依赖从哪来、
   版本是什么、md5 对不对"。

## 复评触发

新增外部依赖 / 更换依赖分发方式（如 fork 改 pip 发布）时更新
`env_probe` 的候选列表；`env_probe.py` 是唯一允许写默认路径的文件
（审计白名单）。
