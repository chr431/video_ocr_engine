## 4. C-57 根治专项：代码级根因定位（本日调查，未动调度机）

审计轮已给根因方向（迟包供给 / 排空 marker 区分）；本日把缺口定位
到代码级，专项实施按此下手：

1. **demux 停读门的供给判定只看游标 GOP**
   （`hybrid_threaded_decoder.h::NeedsPackets()` →
   `HasPartialSupplyLocked()`）：游标 GOP「已派侧且未供完」才放行
   demux。但已派且**未闭合**的 GOP（窗缘落在其中、下一 keyframe 未
   读）的主区间判定 `fed_upto < cache_seq_` 为假（缓存里有的都喂了）
   → 返回 false → demux 停 → 该 GOP 尾部包永不进缓存。
2. **排空判定的空真**（`pump.cc::PumpFeed` gi<0 分支）：
   `all_assigned_fed` 对未闭合 GOP 以 `avail_end=cache_seq_` 判定已
   喂——缓存截断点即「已喂完」，空真通过 → 窗界 flush 合法化。
3. **晚起点的窗计数算术**：window=assigned 计数（seek 后清零重计），
   锚点 GOP 前缀计入预算 → 消费端请求跨度可超出窗覆盖（start≥窗长
   必然；实测损坏 [5980,6000) 而 [5950,5980) 位级正确，边界算术需
   `DECORD_HYBRID_DEBUG` 实测核对，非纸面可推）。

**修复设计**（专项）：①已派 GOP 供给按 GOP 闭合对齐（demux 停读门
加「最后一个已派 GOP 未闭合则继续读」——超读 ≤1 GOP 有界）；②排空
marker 区分真 EOF 与窗界（窗界排空不推全局 `eof_pushed_` 语义或单独
marker 类型）；③晚起点窗语义设计（`SetDecodeWindow` 是否应感知 seek
目标/请求跨度——涉及 API 语义，须契约面变更单列）。

**门禁**（冻结后调度改动专属）：窗口矩阵全格（三码 ×
start∈{0,5000} × win∈{1000,3000} × {有窗,无窗} 位级对照 cpu/nvdec
基线）+ 金标 28/28 + run_fast 六套件 + stream ×10 + 引擎 e2e 段数
恒定。本日不动调度机（审计轮同判：仓促做违反纪律）。

## 5. GPU 侧 EOF 恢复网对称扩展 v2（fork 06923de）

R3-1 裸对称扩展回退的真机理（回退注释留档）：av1 整文件进 512MB
包缓存时 `eof_pushed_` 在**消费中段**即置位，GPU 臂池互锁的**合法**
停滞 ≥3s 被 1s 网误关有帧 chunk → 帧永久丢失 → stream 3/5 FATAL。
v2 = 对称 + **真·尾部判别门**：GPU 侧 `side_pending_[s]==0` 才允许
强关（合法互锁停滞必然 pending>0，天然豁免）；CPU 半边保持首轮语义
（16/16 绿证据面，不加门——软解无池互锁类合法长停）。

验证（dev `f71e8ca2`）：stream **10/10** ALL PASS（同套件 R3-1 裸
对称版 3/5 FATAL；10 连全绿且零 `[hybrid] GPU arm stalled` / 零
force-close 打印）+ run_fast 六套件 + 金标 28/28（dev DLL，见 §6
汇总）。
