## 2. 根因（完整因果链，全部实证）

1. `seek_accurate(5000)` 首次落锚会话（seek 内部 CheckKeyFrame 二次
   Seek/落锚修正）被 `ResetRouting` 切断时，`pending_kicks_` 里的
   换侧 kick（dst=旧会话侧分配）**未被清理**——ResetRouting 重置清单
   逐字段审计：emit_queue_/stash_/pkt_cache_/gops_/各队列全清，
   **pending_kicks_ 是唯一漏网项**（kick_side_/kick_owed_ 清了，
   pending_kicks_ 漏了）。
2. 僵尸 kick 携带旧会话的 `dst`/`after_gop` 进入新会话；侧分配是
   速率感知的（随时序变）——新会话把僵尸 pts 所属 GOP 分给了
   僵尸 dst 同侧时（第二颗骰子），流序注入条件
   `dst==s && g.id>after_gop` 命中。
3. 克隆包（该 GOP 关键帧）发给**拥有该 GOP 的一侧** → 该侧把自己
   GOP 的关键帧解码两遍 → chunk `emitted` 虚增 → 提前关闭 →
   末帧被陈旧丢弃。**帧数守恒、win_subs=0（静默）**、
   221 帧分歧 = 首帧重复 + 移位 + 末帧缺失，签名逐项吻合。
4. 布局双骰子解释历史不稳定复现：①旧会话 flush/backstop 是否在
   二次 Clear 前跑完（跑完=无僵尸=干净）；②新会话侧分配是否撞上
   僵尸 dst。任一骰子避撞即 0/8，双中即 9/12。

## 3. 修复（fork supervisor.cc，一行 + 注释）

```cpp
pending_kicks_.clear();   // ResetRouting 内，与 stash_/emit_queue_ 同批
```
