# 2026-09-18 hybrid 启动轮：速率未熟挂起分配 + rg 生产侧 sustained

> 问题（用户）：解决 hybrid 启动慢；让 hybrid 与单解码器更快交叉；优化
> 引擎内耦合损失（用户纠正：不是 fork 级对并联和的打折，而是 §11.14 归因
> h264 引擎反转的耦合损失——怀疑三码皆有，hevc/av1 被天然优势掩盖）。
> 本轮改 **decord fork**（13d509d，含 4af9b66 硬窗界的补提交），引擎零改动。

## 1. 机理定位（先量后做，_probe_hybrid_startup.py 新探针）

fork 级冷进程诊断（hevc w3000，hybrid_gpu ctx，硬窗界+TRACE 轨迹）：

| 读数 | run#0 | run#1 |
|---|---:|---:|
| wall | 1.532s | 1.876s（gpu-only 1.474s） |
| 盲派 GOP 数 | **10/13** | **13/13** |
| assigned c/g | 1200/1920 | 1680/1440 |
| 稳态份额（share_bp） | 3163 | —（速率从未双熟） |
| rg 终值 | 2168 | **13402**（爆表） |

两个机制：
1. **盲派**：demux 远快于解码（包缓存 512MB ≥ 窗口体积，一次性读至
   EOF），rc 出版要等 CPU 臂解满 4 折×16=64 帧（hevc ~85ms+启动），此间
   已关闭的 GOP 全部走 `PickFeedSide` 的 50/50 交替保守分支 → CPU 臂
   超分 ~200+ 帧 = 慢臂尾部 0.24s+。
2. **rg 爆表**：GPU 侧落地速率还是旧段式 EWMA（快升 1.3×/慢降 5%），
   冷启/排空段把"预缓冲排空速度"孤峰直接出版（13402fps → f 被压到
   6%）——CPU 侧 2026-09-12 已用 sustained 修掉的同款病；run#1 速率
   全程未双熟，13 GOP 全盲派，wall 1.88s。

## 2. 修复（decord 13d509d；全部实测/库存杠杆，无速率先验）

1. **PumpFeed 熟前挂起**：rc/rg 任一未出版 → 未分配 GOP 挂起（留在包
   缓存，零成本——包缓存即为此设计）；配套：flush 抑制（挂起未派完≠
   流结束）+ **Pop 空取路径重驱泵**（EOF 后 Push 停驱的唯一驱动源；
   Pop/Push/PumpFeed 同在消费线程，单线程不变量保持）。
2. **防饿死盲派**：某侧空转（`side_pending_==0`）时盲派给空侧——纯
   库存读数，不含速率假设；双空走 PickFeedSide（gop0 GPU 起步 / gop1
   CPU 采样语义不变，FORCE_SIDE 亦经它生效）。效果上"哪侧先饿哪侧
   拿 GOP"= 用库存读数实现了无需速率数的比例派工。
3. **rg 生产侧 sustained**：折计时从落地线程迁到 CU display 回调
   （逐帧触发，签名 +marker 标志）——落地线程排空 reorder 积压时量到
   的是 D2H 提交速度（h264 尾部假折 **689655fps**），生产侧=NVDEC
   硬件解码节奏与积压无关（与 CPU 臂 filter 线程口径对齐）；出版改
   8 折环 max(连续 4 折最小值) + 0.997/折慢降锁。

交付层事件驱动（§11.14 留档方向①）查实**早已在位**（5433bcb 已接
gpu_/cpu_ on_output + 双池 on_release → lcv_ 唤醒；wait_for(1ms) 只是
超时上限非轮询粒度）——本轮不再动。

## 5. 耦合损失复测（用户怀疑的第三点）

同日同协议配对：fork 级单跑（_probe_hybrid_startup 全片）vs 引擎内
decode.batch（本轮 A/B registry 热轮）：

| 码 | fork 单跑 | 引擎 decode.batch | 耦合损失（修前） |
|---|---:|---:|---:|
| hevc 全片 | 8.52–8.55s | 8.25–8.42s | **≈0**（h264 口径修前 −28%） |
| av1 w3000 | 1.24–1.25s | 1.19–1.20s | **≈0** |
| h264 全片 | 1.98–2.04s | 2.13–2.18s | **≈−6%** |

用户怀疑证实（对旧码）：耦合损失三码皆在，主体经由**速率学习被消费
节奏污染**（盲派交替+rg 排空假折）兑现——修后 hevc/av1 归零，h264
残余 ~6%（两臂协同的结构成本，HOL/对齐/搬运——§11.14 方向①的谓词
等待级优化空间，未实施）。注意口径保留：fork 探针与引擎消费者的批
节奏不同，±几个点内有协议不对称；结论载体是"28%→6%"的量级塌缩。
h264 选型结论不变（C-53：选 cpu）。
