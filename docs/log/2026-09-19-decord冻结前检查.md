## 2. 已修：三项必修

### 2.1 真 bug：`cuMemcpyPeerAsync_v2` 符号名错（多卡静默数据损坏）

**实测证据**（本机 nvcuda.dll，用 decord 自己的 `LoadLibraryA`+`GetProcAddress`
路径）：

| 符号 | 本机驱动 |
|---|---|
| `cuMemcpyDtoH_v2` / `cuMemcpyHtoD_v2` / `cuMemcpyDtoD_v2` / `cuMemcpyHtoDAsync_v2` / `cuMemcpyDtoHAsync_v2` / `cuMemcpyDtoDAsync_v2` / `cuMemcpy2D_v2` | **全部 OK** |
| **`cuMemcpyPeerAsync_v2`** | **MISSING** |
| `cuMemcpyPeerAsync`（无后缀） | **OK** |

即：同类 `_v2` 符号驱动都有导出，**唯独它没有**；且 `cuda.h` 里根本没有
这个名字（`grep -c` = 0）——它是 0.8.1 去 Toolkit 化时手写声明写错的。

**后果链**：符号恒 nullptr → wrapper 返回 `CUDA_ERROR_NOT_FOUND` → shim 映射
成 `cudaErrorInitializationError` → **唯一调用点 `cuda_device_api.cc:150` 裸调用、
返回值被丢弃** → 静默失败，目标缓冲保持未初始化。本机单卡永不触发，
**多卡机器上会静默产生垃圾帧**。

**修复**：decord 的 `src/video/nvcodec/nv_gpu_dyn.{h,cc}` 与 `src/runtime/cuda/cudart_shim.cc` 三处去后缀
（保留 `#undef`，因 cuda.h 无此宏重定向）；调用点补 `CUDA_CALL` 检查返回值。

### 2.2 定时炸弹：decord 仓的 decord 仓的版本更新脚本 `update_version.py` 停在 0.8.1（历史遗留）

decord 仓的版本三源（libinfo / pyproject / c_runtime_api.h；均为 decord 仓文件，不在本仓）现为 `0.8.3`，
而该脚本的 `__version__` 是 `0.8.1`——谁跑一次会把三处**降级**。已改为 0.8.3。

### 2.3 幽灵开关：`DECORD_HYBRID_AV1_CPU`

注释两处宣称「`=0` 可关 AV1 混跑（复评用）」，但代码里**没有这个 `getenv`**
（`grep` 只命中注释）。照注释设 env 会静默无效、让人误判"混跑不可关"。
**修复：补上真实开关**（`av1_cpu_off` → 非 IDR 码恒走 GPU），保留注释承诺的
复评能力。

## 3. 已清：死代码与死开关

### 3.1 六个零设置者 env 开关（固化默认行为后删除）

`HOLD_OFF` / `TAIL_OFF` / `RESPLIT_OFF` / `FORCEREDRIVE_OFF` / `TRACE2` /
`NO_EXPECTED`——每个全仓（decord + 引擎）只有定义处一处提及 = 零设置者。
均为前几轮排查时加的消融开关，用完未清。删除后行为等于原默认值。

### 3.2 死代码

- `FeederLoop()`：只有声明无定义（喂包逻辑已并入 `GpuWorkerLoop`），
  头注释还描述着已不存在的双线程模型；
- `arm_kick` 恒假分支（唯一赋值点在 `fef3c4b` 重设计时删除）+ `kick_dst` 死变量；
- `EnableReleaseSync()` / `WaitRelease()` 整对 + `release_ev_` / `sync_stream_`
  两个成员（`5433bcb` 只加定义从未调用，当前实现走 `SetOnRelease` 事件驱动）；
- 8 个零引用成员：`RankOfPts`（定义+声明）、`gpu_pending_`（7 写 0 读）、
  `cur_gop_pkt_begin_`、`kStickyMinChunks`、`pts_per_frame_`、`started_`、
  `FramesDecoded`、`MarkDisabled`（保留，有测试/降级用途）；
- `nv_gpu_dyn.h:60-66` 重复的 `#undef cuMemcpy2D` 块。

### 3.3 构建配置

- `cmake/util/FindCUDA.cmake`（158 行）：`CMakeLists.txt` 从未调用，且内容
  （找 cudart/nvcc/cudnn）与现行「零 Toolkit」模型**完全相反** → 加 DEPRECATED 标注；
- `gpu.Dockerfile:48`：原 `python3 setup.py install` 依赖的打包脚本已被 fork 删除（历史遗留）→ 改 `pip3 install .`。

### 3.4 一处纠正子代理结论（诚实记录）

子代理判定 `DECORD_HYBRID_KICK_BURST`「完全无效」——**过强**。实际：
`kick_guard_` 默认改为 **0** 是**有意的**（注释说明旧反馈式清偿会活锁：
hevc 12000 帧实测挂死），但 `KICK_BURST>0` 仍能覆盖它、使克隆分支可达。
真正死的是 `arm_kick` 那个分支（已删）。

**但连带发现一处跨仓失真**（已修）：引擎 `_probe_release_gate.py` 第 6 步的
头部说明写「KICK_BURST=0 期望超时挂死（反馈清偿承重）」——该机制已随
`fef3c4b` 删除，**旧判据测的东西不存在**（实现早已改为"优雅降级守护"，
只有文档没跟上）。已更新文档说明。

## 4. 已做：`nvml.h` 手写替代（省 795KB）

原 `cuda_include/nvml.h` = **14,546 行 / 795,795 字节**，而 fork 只用 **4 个符号**
（`nvmlReturn_t` / `NVML_SUCCESS` / `NVML_SYSTEM_DRIVER_VERSION_BUFFER_SIZE` /
两个函数指针），且全部只服务一个判断：驱动内核模块版本是否 ≥ 384（决定用不用
自建 stream）。

**替代**：`src/video/nvcodec/nvml_min.h`（~45 行，值与官方头 ABI 一致；
NVML 自 2012 年起未变）。头内注明：若将来需要更多 NVML 能力（温度/时钟/功耗），
**应恢复官方头而非在此堆叠**。

**验证**：重建后 NVDEC reader 正常打开（该路径会走 NVML 版本探测）。
