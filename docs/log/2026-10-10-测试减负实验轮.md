# 2026-10-10/11 测试减负实验轮（用实验说话：时长 × 可靠性）

目标：简化实际要跑的测试内容，标准化脚本适当减少重复次数——**前提是
不损害数字可靠性**。方法：先实测各入口成本分布，再对每个"重复次数"
用实验/统计证据裁决。结论先行：**最大的时间开销不是重复次数，而是两
个互相掩护的失效守卫 + 一个只在负载下显现的遥测成本回归**；修复后全
部预算无需降低重复次数。

## 起点：测试入口成本摸底（本机实测）

| 入口 | 实测 | 备注 |
|---|---:|---|
| pytest 全套（293 用例） | **126.2s** | 单个测试占 94.6s（75%） |
| 金标 full（33 用例） | 71.9s | smoke 层 **6.7s**（10.7× 差距） |
| window matrix 单轮 | 41.9s | 发布门禁 ×5 ≈ 3.5min |
| decord run_fast 七套件 | 346.2s | md5 15.4 / window 26.6 / stride 27.2 / formats 98.2 / stream 109.7s |

## 发现 1：确定性成本守卫自诞生起形同虚设

`test_full_recording_path_cost_per_run` 占 pytest 94.6s，且**从未真正
测过它要测的东西**：`_median_cost` 循环硬编码 `Metrics("full")`（tier
参数只影响预热），所谓"full−off 增量"实际是 full-vs-full 自比——插桩
膨胀永远测不出（考古：c27ec6b 09-17 首版即硬编码 std，0.22.0 改 full）。

94.6s 的直接原因：每轮重放新建 Metrics 实例 → checkpoint 惰性构建资源
探针 + （后见发现 3 的）全线程快照 ≈ 155ms/次 × 600 次。

修复：`Metrics(tier)` 恢复生效 + 预算拆分重推导（记录面增量 ≤2.0ms、
相位采样面 ≤2.0ms、直方图 ≤8.0ms——合计正好对齐 D30 墙钟预算 1.2%）。
bootstrap 证据（bench/replay_cost_samples.json）：增量点估计 0.93ms、
余量 53%，**n=30 时 P(误报)已为 0**（p05–p95 ±0.004ms）——REPLAYS=300
纯属白拿的稳定性，保持不减。测试文件 94.6s → **1.18s**。

## 发现 2：full 档遥测成本回归 +4.4%（PI-15 实测复现后修复）

修好守卫后跑 PI-15 墙钟门禁（off vs full 配对 25 对）：**+4.385%
（SE 0.047%，25/25 符号一致）→ 失败**。逐层归因（配对二分）：

- 采样线程（NvmlSampler）：−0.17%，噪声内，无罪；
- GC：两档均 3 次 gen0，无罪；
- 逐类封禁：封 checkpoint 收回全部 133ms → ThreadLedger 部分；
- 仪器化：`sample_all()` 负载下 **40.7ms/次 × 4 = 164ms**（空闲实测
  0.11ms——空闲结论在负载下失效）；
- 终因：快路径的**信任门一票否决**——首跑对账遇线程生灭，TID 集合
  瞬态不一致 → `_nt_trusted=False` 永久回退 Toolhelp 慢路径（39ms/次，
  实测 4 次 158.8ms）。

机制澄清：慢不在 GIL（对已注册线程的 `sample()` 同为逐线程 Query，
0.016ms）——**对正在满载运行的外来线程做 QueryThreadCycleTime 本身在
内核侧就贵**；空闲基准测不出它。

修复：对账改**集合相似度判据**（交集 ≥90% × min，容忍生灭；值无需
校验——两个路径的 cycle 都来自对正确 TID 的内核真查询）+ 连续 3 次
不过才永久回退。修复后 PI-15 **+0.098% → 通过**，wall 3.122s（恢复
136ms），稳态 NT 12 次 3.41ms / Toolhelp 0 次。

结论：C-62~C-67 的相对结论不受影响（该成本在对比臂间共模）；bench
registry 里 10-09 之后 full 档的**绝对**墙钟携带 ~4% 共模税，解读时注意。

## 发现 3：A/A 标定的 inner 权衡（floor 曲线，bench/aa_floor_curve.json）

同机顺序采两组 A/A（h264-gpu，window 3000，n=25）：
- inner=3（150 次 run，~500s）：本组被瞬时事件污染（单槽 +34%/−9.8%
  离群 → floor 5.3%）——**均值+3SE 对离群敏感，标定值异常时重跑**；
- inner=1（50 次 run，178s）：floor **0.50%**，bootstrap p50 0.45%、
  p95 0.85%。

两组都 ≪ 门限 1.20% → **成本门禁配方 = `--inner 1`**（3× 便宜）；
µs 级 micro 对比（--full-limit 0.2~0.3）仍用 inner=3 + n=50。已写进
`bench.py --inner` 帮助文本；默认值不翻（标定连续性优先，单会话证据
不足以推翻既有标定协议）。

## 落地

1. **两级标准化入口 `tools/check.py`**：daily（pytest+快检+金标 smoke
   ≈47s）/ release（全量审计+金标 full+发版清扫 ≈2min），每步计时汇总，
   无视频环境自动跳金标。rules.yaml 门禁规则更新指向它（原"28/28"计数
   已过时——金标现 33 用例）。
2. pytest 全套 **126.2s → 29.3s**（4.3×）；日常链（check daily）≈47s。
3. decord 侧：README 测试节补实测套件耗时与**核心三件**日常子集
   （md5+stride+window ≈70s vs 全量 346s）；合入/发版仍全量。
4. 预算与守卫：测试预算三项拆分（见发现 1）；PI-15 与重放守卫的分工
   成文（重放抓恒定病理、墙钟抓负载病理）。
