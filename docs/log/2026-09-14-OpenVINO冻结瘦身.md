# 2026-09-14 OpenVINO 冻结包瘦身：227MB → 73MB（CPU 最小集实证）

> 命题（用户）：开发环境体积不敏感，但冻结 exe（分发软件）要尽可能小。
> 发行 wheel 是全家桶（NPU 编译器/GPU 插件/各家前端/C 头文件全带上），
> 本项目只用 CPU 设备——剪掉其余并实证等价。

## 1. 成分账（本机安装 227MB，2026.3.1）

| 成分 | 大小 | 去留 |
|---|---:|---|
| `libs/openvino_intel_npu_compiler.dll` | 82.4MB | 删（Intel NPU 编译器） |
| `libs/openvino_intel_cpu_plugin.dll` | 46.3MB | **留** |
| `libs/openvino_intel_gpu_plugin.dll` | 34MB | 删（Intel GPU，需 OpenCL） |
| `libs/openvino.dll`（核心） | 16.2MB | **留** |
| `libs/cache.json` | 8.8MB | 删 |
| `libs/openvino.lib` | 8MB | 删（C 链接库，Python 运行不用） |
| `libs/openvino_intel_npu_plugin.dll` | 7.2MB | 删 |
| `libs/openvino_onnx_frontend.dll` | 4.8MB | **留**（ONNX 模型解析） |
| tf/pytorch/paddle/tflite 前端 dll | ~9.3MB | 删 |
| `include/`（C 头文件） | 4.7MB | 删 |
| `frontend/`（Python 前端 pyd×5） | 2.9MB | 删（compile_model(路径) 走 C++ 前端） |
| `tools/`、auto/hetero/autobatch、tbb *.lib/_debug | ~2.5MB | 删 |
| `_pyopenvino.pyd`、tbb12/tbbmalloc(.dll)、包 py+opset | ~2.5MB | **留** |

**剪后 = 73MB（−68%）**；设备表从 `[CPU, GPU]` 变 `[CPU]`。

## 2. 等价性实证

1. **模型级逐位**：同随机输入（B18/W224，seed0），完整安装 vs 剪枝副本
   输出 `np.array_equal == True`、max|Δ|=0.0。
2. **引擎路径**：`PYTHONPATH` 指剪枝副本跑 FieldExtractor（h264-cpu 3000
   帧）→ 1090 段，与金标 case-A-cpu-p0-cpu 记录的 n_segments 恒等。
3. 剪枝副本在 `bench/ov_pack/`（gitignore 内，可重建：配方见上表）。

## 3. 冻结配方（PyInstaller 同理适用 cx_Freeze/Nuitka）

- 正常打包（pyinstaller-hooks-contrib 的 openvino hook 会收全量），
  **构建后剪枝** `_internal/openvino/`：按 §1 删表清理 `libs/` 与
  `include|tools|frontend` 目录。
- 打包脚本化（`--exclude-module` 只挡 Python 模块，挡不住 DLL 收集，
  故剪枝必须在构建后做文件操作）。
- **验证门**：冻结产物跑 600 帧抽提（段数与全量安装恒等）+
  `ov.Core().available_devices == ['CPU']`。
- 可选加压：UPX 对剩余 DLL 再省 30~40%，但个别 AV 加误报/加载变慢，
  默认不开。
- 冻结体积叠加项：若同步移除 onnxruntime（另案），再省 ~45MB。

## 4. 复评触发

OpenVINO 换代（libs 布局/插件名变）/ 需要 NPU·Intel GPU 设备时重剪。
