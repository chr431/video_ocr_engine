| 配置 | 聚合吞吐 |
|---|---:|
| t8 单流同步（旧参照） | 27.4 批/s |
| t8 单流经 AsyncInferQueue（jobs=1 流水提交） | 40.1 批/s |
| t16+NUM_STREAMS=2 | 67.8 批/s |

（提交流水化本身就有收益）。集成设计：ocr_instances 的 OV 路径改
单引擎 + AsyncInferQueue（jobs=2，worker 各占槽位，infer_worker
结构不变）；knob 默认关，门禁 = bench ab + 真值 + 金标。


## 5. 集成裁决（同日续二）：多流引擎级判死 + 预处理融合判死

**多流（AutoInferQueue 单引擎槽位式，已实现后撤销）**：全片逐位一致
（2735 段全字段，安全达标）；交错 A/B（h264-cpu 热池=生产口径）：
- OCR_OV_STREAMS=AUTO（8 流×2 线程）：**+5.35% 劣化（3/3）**——逐请求
  线程过少，延迟劣化吞掉聚合增益；
- OCR_OV_STREAMS=2（16 线程对半）：热池 **+0.44% 平价（符号乱）**；
  冷启动 −6.26%（单编译 vs 双编译，非生产口径）。
- 结论：模型级 +27% 聚合不构成为引擎收益——OV 2.1× 落地后 CPU 路径
  墙钟已非 OCR 吞吐绑定（预处理/解码共绑），多流只改吞吐不改延迟链。
  与 C-47 同判例（微基准差 ≠ 管线可回收）。集成代码撤销（含 _infer
  锁旁通——热路径复杂度不为平价保留）；旋钮未入库。

**预处理融合（PrePostProcessor）**：成分实测（µs/段，105×32 裁切）：
灰度 3.1 / **resize 120.1** / gamma 14.5 / 归一化+pad 9.9。可融合面
（仿射归一化+pad，preproc 原生支持）= 9.9µs ≈ **全片 0.027s / 6.3s
= 0.4%**——判死。开销大头 resize（120µs）被 gamma 位置锁死在图外：
gamma 位于 resize 与归一化之间，非线性与线性插值不可交换序（09-13
"灰度先行"等价性靠的恰是双线性），OV preproc 无 pow 算子；把 gamma
前移到 resize 前 = 数值语义变更（需全套真值门禁，收益上限也仅 ~11%
且 OV resize 是否快过 _np_resize 未证）。复评触发：OV preproc 出
pow/自定义算子，或 gamma 语义变更被单独立项。

**两项裁决后 CPU 路径的剩余墙钟 = 结构性（解码/预处理/推理共绑），
OV 侧无剩余便宜杠杆。**
