# v5 调度重设计：动态领用 + 自调速的 work-stealing 混合解码

## 为什么要重设计（实测依据，本轮会话测得）

双解码器在不同硬件上，理论上 decode 时间 = N/(rf+rs)，应快过任何单端。现状：

| 场景 | NVDEC | CPU | hybrid decode | 理论下界 | 平行效率 |
|---|---:|---:|---:|---:|---:|
| test2 HEVC s8 | 1.206s | 1.452s | 0.974s | ≈0.68s | **~46%** |
| test6 AV1 s8 | 1.542s | 4.68s | 1.084s | ≈1.22s¹ | ~100%¹ |
| test5 h264 s1 | 3.016s | 1.05s | 1.13s | ≈0.80s | 负收益（慢端拿了 4/11 片）|

¹ AV1 校准噪声所致，实测 hybrid≈NVDEC独跑-CPU 少量贡献。

结构性缺陷（现有 v4 调度）：
1. **分界是静态的**：校准一次定终身（预算 40-240 帧实测都测不准 h264 的 2.6× 速率差），错配无法运行时纠正，只有"快端扫完自己区"才开始接管——接管太迟。
2. **接管只能救火不能均衡**：慢端区空即退，快端等自己区扫完，两端不共享一个按序的领取队列。
3. **校准阻塞生产**（仅 h264 之外的 HEVC/AV1 有重叠空间）。

## 设计（v5）：单按序领取队列 + 实时速率份额

保持已验证的正确性骨架（kfe 分片、连续扫掠免 seek、inflight 内存上界、全局序交付、deque 消费），替换静态分界：

**核心机制**
- 共享一个按序领取指针 `self._next`；两个生产者都从队头领取未认领片（一次领一个 RUN，RUN 大小=1 片起步）。
- **份额控制取代静态 split**：每个生产者维护自己片尾的"已产出未消费帧数"（现有 `_unconsumed` 计数扩展为帧数）；领取条件 = `我的未交付存量 ≤ remaining_total × share_me`，其中 `share_me = live_rate_me/(live_rate_fast + live_rate_slow)`。
- **live_rate 用生产者实际产片计时自测**（每片完成时 EMA 更新，天然稳态、无校准噪声、无争抢失真）——校准退化为只决定初始 5 秒内的种子份额 + 决定 CPU reader 打开后的启动顺序。
- **连续扫掠不变量保持**：领取总是从队头按序，一个生产者的领取序列天然连续（除非被对方抢先领走一片，则它 seek 一次接上自己下一个领取点——与 v4 接管同频）。每生产者 seek 次数仍是 O(区切换)，被 `test_hybrid_producer_stride` 精神覆盖，会补新测试。
- **慢端保护**：领取上限（`inflight` 帧数化，总内存上界不变）+ `share` 上限防错摆。
- **h264 场景自动退化**：当 live 份额显示 CPU 占 ~100% 时，GPU 自然领不到片（share≈0.26 → 校准种子期后 GPU 存量超限即停领）→ 无需任何 codec 阈值分支。

**启动路径优化（并入）**：GPU 校准线程结束后就地生产片 0（本轮已实现并验证正确的 early-start，v4 里它是独立的 0.03-0.08s 收益，在 v5 里成为份额种子的第一个观测点）。

**弃用**：`_split_idx` 静态语义、`_dynamic_split` 调用点。`_dynamic_split` 纯函数与其单测保留（降级为 share 钳制参考 + 回归护栏）。

## 实现改动

- `hybrid_decode.py`：
  - `_chunks` 字典加 `claimed`（替代 `started` 双语义）；`self._next`、`self._share=[seed_fast, seed_slow]`、`self._live={fast:fps, slow:fps}`。
  - `_take_chunk(who)` 重写为按序领取 + 份额判定（`_cv` 内完成，无新锁）。
  - `_produce_chunk` 完成处：EMA 更新 `self._live[who] += 本次片实测 fps`；重算 `self._share`；`notify_all`（让等待领取的对端立即复核）。
  - `hybrid_begin`：校准并行不变；校准后用 rf/rs 只算种子份额；GPU 校准线程就地生产片 0（本轮已写的 `_gpu_head_produce` 简化版接管，去掉 `_split_committed` 暂分界机制——v5 无静态分界可言）；join 顺序：等 GPU calib event + CPU calib thread，然后起 CPU 生产者。
  - `_unconsumed` 语义从片数改帧数（内存上界 env 换算：`inflight × 片均帧数` 保持近似；`HYBRID_SLOW_INFLIGHT` 兼容：读作"片数×平均" 或直接用帧预算常量，实现时定，测试钉死）。
- `engine_config.py`：新增 `HYBRID_SHARE_CAP`（慢端份额硬上限，默认 0.5）、`HYBRID_LIVE_EMA`（EMA α，默认 0.3）。
- 测试：
  - 新 `tests/decode/test_hybrid_steal_scheduler.py`：纯逻辑桩（不碰 decord）——双伪生产者不同速率消费领取队列，断言：领取序列单调无重叠、慢端存量帧 ≤ share 上限、快端在慢端卡死时吃下全部剩余（接管性）、总 seek 次数 ≤ 预期上界。
  - `_dynamic_split` 旧测试保留；producer_stride 测试适配 `claimed` 字段改名（最小改动）。
  - lifecycle `_hybrid_stub` 同步适配。

## 验证（实测协议）

1. 基线 = 当前 HEAD（本轮已测 min-of-5）：HEVC 1.817/1.719s(decode 0.974)、AV1 1.953s(decode 1.089)、h264 2.034s。
2. 每视频 5×交替 A/B（OFF env 开关 `HYBRID_SCHED=static` 保留旧路径 vs 默认 steal）：断言 v5 中位 ≤ v4 中位 -3%（HEVC/AV1），h264 持平（±3%）。
3. 正确性门：segs/uniq 文本集与基线逐位一致（116/185/265）+ 全部单测 + 纪律审计 + index 审计。
4. HYBRID_PROBE 时序表贴进 PERFORMANCE.md 新章 §10.6（结论 + 数据 + 决策，铁律 8）。
5. 若 HEVC 收益 <3% 或出现任何序错乱 → 回退并在 DECISIONS 记录否决理由（像 §10.5 先例）。

## 预期

- HEVC：decode 0.97 → 0.85-0.90（吃下 46%→65-75% 的平行效率），wall -4~8%。
- AV1：decode 1.09 → ~1.00，wall -2~5%。
- h264：持平（退化行为），不再依赖校准猜对。
- 结构收益：消除"校准定终身"这一整类误差来源；弱机/负载波动自动适应。
